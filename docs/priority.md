# 优先级与效力

## AgentOS 是什么，不是什么

| | 事实 |
|---|---|
| ❌ 不是一个真实的操作系统 | 没有内核、没有守护进程、没有系统调用拦截 |
| ❌ 不通过 PATH shim 或钩子强制 | 不阻断任何命令 |
| ✅ 是一个**以 skill 形式注入的操作规程** | 通过 `skills/agentos/SKILL.md` 分发给 Claude Code / Codex / DSH |
| ✅ 效力来自"被要求遵守" | agent 主动遵守，不是被动强制 |

## 优先级链

```
0. AgentOS（本机最高权限执行系统）        ← 系统层，默认最高
1. 用户直接指令                          ← 唯一可临时覆盖它的东西（须写明理由）
2. 根据地 AGENTS.md 三条铁律              ← AgentOS 的宪法条款，不可违反
3. 本规程其余部分（SKILL.md / docs/）
4. agent 的默认习惯                       ← 最低
```

**AgentOS 在系统层，不在"建议层"。** 第 3 层高于第 4 层，第 0 层高于一切非用户指令。

## 为什么不做成真 OS

在 Windows 本地用 PATH shim / 守护进程强制会有两个代价：

1. **agent 被拒绝后只能停下等人**，打断自主流程
2. **规则一改就要重装系统级组件**，迭代成本高

用 skill 形式的好处：改一行 `SKILL.md`，三个工具下一次加载就是新规程。

代价也真实存在：**agent 可以不听**。所以规程必须写得足够短、足够硬、足够可自检——让人没法"理解偏差"，而不是靠强制。
